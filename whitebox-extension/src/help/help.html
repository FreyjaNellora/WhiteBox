What WhiteBox is

WhiteBox is a portable user-memory layer for AI agents. It lets Claude, ChatGPT, Gemini, and other AI tools you use all read from — and write to — the same set of markdown files on your own disk. You own your memory, and it travels with you across every agent.

This extension is one of three ways to connect your vault to an AI:

  1. Browser extension (what you're reading about) — works on claude.ai, chatgpt.com, gemini.google.com.
  2. MCP server (whitebox-mcp) — works with Claude Desktop, Claude Code, Cursor, Gemini CLI.
  3. CLI (whitebox paste) — works anywhere you can paste text (mobile, random chat clients, API consoles).

Your vault folder

Your vault is a folder on your computer that holds markdown files describing you, your preferences, and the observations agents have made about you over time. The extension reads and writes to this folder via the File System Access API, which requires you to explicitly pick the folder once.

To connect a vault, click the WhiteBox icon in your toolbar → Open setup… → Choose vault folder, and select the folder.

Don't have a vault yet? Create one by running whitebox init in a terminal, or make any folder with an AGENTS.md inside it. The QUICKSTART walks through the full setup.

Grant lasts for the browser session. After you fully restart your browser, the permission decays and you re-grant via the same Setup page with one click.

Bootstrap injection

When you start a new conversation on a supported site and have WhiteBox enabled, the extension prepends a short block of your vault's context to your first message before it's sent. Specifically:

  • The contents of AGENTS.md (instructions on how the AI should interact with your vault)
  • Your identity.md (stable facts about you)
  • Your working-style.md (how you want to be worked with)

It shows up as a visible block at the top of your first message, wrapped in <!-- whitebox-context: start --> markers. Claude/ChatGPT/Gemini read that context and respond accordingly.

Injection only fires on the first message of a new conversation. Subsequent messages in the same conversation don't re-inject; the context is already in the conversation history.

To disable injection on a specific site, uncheck that site in the popup's "Active on" section.

Capture last response

During a conversation, when the AI says something worth remembering, click the WhiteBox icon → Capture last response. A new tab opens with a review form containing the verbatim text of the most recent assistant message.

Fill in:

  • Tags — pick from your vault's tags.md (suggestions show as chips) or type your own (comma-separated). New tags get flagged as proposed for you to curate later.
  • Confidence — how confident you are that this observation is accurate and durable (see Confidence scale).
  • Body — the assistant's response, already pre-filled. You can trim or edit it before saving; the body becomes the observation verbatim.

Hit Save to vault and the entry appends to observations/YYYY-MM.md in your vault.

Session digest

Capture scales poorly if you want to save multiple moments from one conversation. For that, use Session digest… from the popup.

The digest page pulls every turn from the current conversation — both yours and the AI's — and shows them as checkbox cards. Filter by role (user / assistant), scroll through, tick the turns worth saving, set shared tags and confidence once, and hit Save selected. Each ticked turn becomes its own observation with the bulk tags.

Per-turn tagging isn't in this build; the bulk-tags model is a simplification. If it bites, the BACKLOG has per-turn tags listed as a refinement to pick up when it matters.

What gets saved — the verbatim rule

WhiteBox's core promise is trust: every observation in your vault is traceable to a literal moment in a conversation. Agents never paraphrase, summarize, or invent. If the observation body isn't a direct quote, something's wrong.

You, the human, can annotate your vault however you want — edit observation files, add free-form notes, restructure. The verbatim rule only constrains what agents write on your behalf.

An example observation entry in observations/2026-04.md:

---
date: 2026-04-21
source: claude.ai
tags: [working-style, preference]
confidence: high
---

Direct quote from the conversation, verbatim.

Tags

Tags categorize observations so you (and future agents) can retrieve them by theme. Your vault's tags.md lists your canonical tags under Active. New tags proposed by agents or added during capture appear under Proposed until you curate them.

Common tag patterns:

  • working-style — how you want to be worked with.
  • preference — stated likes and dislikes.
  • correction — you corrected the agent on something.
  • relationship:<name> — about a specific person.
  • project:<slug> — about a specific project.
  • conflict — observation contradicts an existing stable fact.

The full canonical tag registry is at spec/tags-canonical-v1.md.

Confidence scale

Five grades, from uncertain to certain:

  • very-low — fleeting impression, weak evidence, might not hold.
  • low — possibly true, one data point, matches a pattern.
  • medium — probably true, consistent across moments.
  • high — clearly stated by the user or observed repeatedly.
  • very-high — explicitly confirmed, identity-level claim.

Confidence matters for future retrieval: higher-confidence observations are weighted more in bootstrap injection (planned), and low-confidence ones age out faster (planned). For now, just be honest about how sure you are.

Scopes (advanced)

If your vault has a scopes.md file and you set an active scope in the popup, WhiteBox will only read and write files inside the matching scope. Use this to keep sensitive observations out of sessions where you don't want them (e.g., a coding session shouldn't have access to your personal journal).

Scope configuration is manual for now — create the scopes.md file in your vault by hand and organize your vault into folders that match scope definitions. See the schema spec for format.

Supported sites

Right now WhiteBox's browser extension works on:

  • claude.ai
  • chatgpt.com (and the legacy chat.openai.com)
  • gemini.google.com

For other sites, use the CLI's whitebox paste command to copy your vault context to the clipboard and paste into any chat manually. For desktop apps that support MCP (Claude Desktop, Claude Code, Cursor, Gemini CLI), use the MCP server instead.

Troubleshooting

"Vault not accessible" or no injection log

Grant probably expired after a browser restart. Click the WhiteBox icon → Open setup… → Re-grant access.

Injection doesn't fire on first message

Usually means the site's DOM structure changed and our composer selector didn't match. Open DevTools (F12) → Console. Look for a line like [whitebox] <site> content script v0.3 live — if that's missing, the extension didn't load. If it's there but no injected N chars log, the composer selector needs updating. Report it as a GitHub issue or PR a selector fix in src/content/<site>.js.

Capture extracts the wrong text or nothing

DOM selector miss. Same as above: Console output + GitHub issue.

Save fails on the propose or digest page

Check the service worker console: chrome://extensions → WhiteBox card → Inspect views: service worker. The specific error will point at the file to fix. Often it's a permission re-grant or a path issue.

Developer-mode warning on every Chrome launch

Chrome nags because the extension isn't from the Web Store. Safe to dismiss. Goes away once we publish to the Web Store (roadmap item).

Privacy

This extension never phones home. No analytics, no telemetry, no external requests beyond the content scripts running on the three AI sites you've enabled. Your vault is on your disk; the extension reads and writes to it via the File System Access API, and nothing leaves your machine without your explicit action.

When you use Capture or Session digest, you're taking DOM text that's already on your screen (that you sent or received in a conversation with an AI) and saving it to your local disk. No third party sees it.

Syncing your vault across devices is your choice: git, Syncthing, iCloud, Obsidian Sync, Dropbox — pick one (don't stack them, conflicts). The extension is not involved in sync.
